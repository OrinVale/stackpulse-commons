# 90-day funding campaign plan

This is an execution plan, not a revenue forecast. It is designed to maximize
legitimate, aligned support without overstating the maturity of the project or
spamming communities.

## Campaign objective

Raise **USD 12,000 over 90 days** for the foundation pilot in
[the public budget](../../FUNDING.md). The more useful near-term measurement is
whether the project reaches the first USD 3,000 milestone and publishes
evidence, not whether a public number looks ambitious.

## Funding mix to pursue

| Channel | Purpose | Campaign target | Prerequisite |
| --- | --- | ---: | --- |
| Direct public contributions | Let aligned individuals support the first milestone | USD 1,000–2,500 | Giveth page, clean public repository, clear funding policy |
| Aligned supporters or sponsors | Seek a small number of larger unrestricted public-good contributions | USD 2,000–5,000 | Brief, budget, milestones, and a specific fit |
| Ecosystem grant | Fund a concrete ecosystem-specific module | USD 3,000–12,000 | A real module that meets the funder's published scope |
| Recurring support | Build a modest long-term base | USD 250–1,000 per month | Public repository plus a stable update cadence |

These are campaign targets, not promises. A generic grant application or an
unfocused mass message should not be counted as progress.

## Conversion assets

Before the first public ask, publish or verify:

1. A clean public repository without historical personal metadata or generated
   databases.
2. The funding policy, treasury address, pilot budget, methodology, roadmap,
   and governance policy.
3. A Giveth project page with a direct repository link and a custom banner.
4. One short visual or dashboard example that demonstrates a source-linked
   delta.
5. A first changelog entry describing what works, what is still a prototype,
   and the next milestone.

## 30-day launch cadence

| Window | Action | Evidence of completion |
| --- | --- | --- |
| Days 1–3 | Publish the project page and unlisted Giveth listing; verify every link, network, and address | Screenshot and link check |
| Days 4–10 | Ask a small number of relevant builders and public-goods operators for candid feedback, not money first | Logged feedback themes |
| Days 11–20 | Send a limited set of tailored support or grant requests where the project genuinely fits | Sent messages recorded privately; no bulk outreach |
| Day 21 | Publish the first technical and funding update, even if funds received are zero | Dated changelog |
| Days 22–30 | Improve the project page using feedback and share one source-linked example | Updated copy and example |

## Request discipline

Every request should answer five questions in under a minute:

1. What observable problem is being solved?
2. What exists today?
3. What specific milestone will this contribution unlock?
4. What will be open and source-linked?
5. How will progress and spending be reported?

Do not use fake urgency, airdrop language, promised returns, undisclosed
affiliate links, or artificial donation activity. Do not claim a partnership,
grant eligibility, user count, or completed deliverable unless it can be
verified.

## Weekly campaign metrics

Track these privately and report only aggregate public figures:

- qualified conversations started;
- feedback received and incorporated;
- public page visits and contribution conversion rate;
- recurring contributors;
- funds received by source and asset;
- days since the latest delivery update;
- progress toward the USD 3,000, USD 8,000, and USD 12,000 milestones.

The campaign should be stopped or narrowed if feedback repeatedly says the
public benefit is unclear. In that case, use the evidence to improve the
pilot rather than increasing message volume.
